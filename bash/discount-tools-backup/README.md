# Резервное копирование discount-tools.ru

Bash-скрипт для резервного копирования файлов Bitrix и базы MySQL на FTP. Версия пакета: 2026-10-23. Основа - скрипт с диагностикой tar/curl, успешно проверенный на сервере 09.10.2026. Более поздние изменения серверного экземпляра в пакет не включены.

## Состав

- `backup.sh` - полный рабочий скрипт с диагностикой потока.
- `examples/backup.conf.example` - конфигурация без реальных паролей.
- `examples/backup.cron.example` - пример задания cron.
- `MIGRATION.md` - перенос, проверка восстановления и откат.
- `.gitignore` - исключения для секретов, логов и архивов.

## Как работает

1. Загружает `/home/script/inc/backup.conf` и блокирует параллельный запуск через flock.
2. Проверяет свободное место и FTP-листинг.
3. Создаёт локальный сжатый дамп MySQL и проверяет его gzip-структуру.
4. Передаёт tar.gz потоком через curl на FTP во временный файл `.part`.
5. Проверяет наличие файла и, если сервер отдаёт размер, сравнивает его с объёмом передачи; переименовывает архив.
6. Только после успешной загрузки оставляет последние 10 подходящих по имени архивов.

Рабочий кэш сайта не очищается. В архив входят скрытые файлы корня, дамп `__backup/<DB_NAME>.sql.gz` и описание `__backup/backup-info.txt`.

Исключены: `bitrix/cache`, `bitrix/managed_cache`, `bitrix/stack_cache`, `bitrix/html_pages`, `bitrix/backup`, `bitrix/updates`, `upload/tmp`, `upload/resize_cache`.

## Требования

Linux, Bash, GNU tar/coreutils, gzip, awk, util-linux (flock, желательно ionice), nice, curl с поддержкой FTP, mysql и mysqldump, msmtp. Нужны доступ к файлам сайта, БД, FTP и настройкам отправки почты. Рекомендуемый запуск - от root, как на исходном сервере. Скрипт использует GNU-опции и не рассчитан на запуск под macOS или `/bin/sh`.

Минимальный порог свободного места потокового режима - 1024 МиБ, но фактически места должно хватать на дамп БД и рабочие файлы. Для локальных архивов предусмотрен порог 5 ГиБ; он не гарантирует, что конкретный сайт поместится.

## Установка

```bash
install -d -m 700 /home/script/inc /home/script/logs
install -m 700 backup.sh /home/script/backup.sh
install -m 600 examples/backup.conf.example /home/script/inc/backup.conf
vi /home/script/inc/backup.conf
vi /home/script/backup.sh
bash -n /home/script/backup.sh
```

В конфигурации задайте реальные пути и реквизиты. В начале скрипта проверьте `CONFIG`, `LOG_FILE`, `LOCK_FILE`, `EMAIL_TO`, `EMAIL_FROM`, `MSMTP`, `MSMTP_CONFIG`, `MSMTP_ACCOUNT`, `BACKUP_PREFIX`. Адреса и пути в скрипте сохранены от исходного сервера. Настройки почты находятся в самом скрипте; режим `--test-email` не загружает backup.conf.

Настройте msmtp отдельно. Его конфигурация и SMTP-пароль в пакет не входят.

```bash
/home/script/backup.sh --check
/home/script/backup.sh --test-email
/home/script/backup.sh --all
tail -n 60 /home/script/logs/backup_v2.log
```

`--check` создаёт и удаляет временные локальные файлы, проверяет подключение к БД и FTP, но не проверяет передачу большого архива и не отправляет тестовое письмо. Полный запуск выполняет ротацию на FTP.

## Режимы

| Ключ | Действие |
| --- | --- |
| `--all` | БД и сайт потоком на FTP, затем ротация |
| `--check` | Проверки конфигурации и окружения |
| `--sql` | Локальный сжатый дамп БД |
| `--site` | Локальный архив сайта без кэшей |
| `--all-noftp` | Полный локальный архив |
| `--clear-ftp` | Ротация FTP и удаление подходящих зависших `.part` |
| `--test-email` | Тест почты |
| `--help` | Справка |

## Автозапуск

После успешного ручного запуска добавьте строку из `examples/backup.cron.example` в root crontab через `crontab -e`. Это пример для пользовательского crontab, без столбца пользователя. Время 01:00 трактуется по часовому поясу cron на сервере. Не создавайте дублирующее задание в панели хостинга.

## Лог и диагностика

Основной лог: `/home/script/logs/backup_v2.log`.

```text
STREAM RESULT: tar_exit=0; curl_exit=0; size_upload=2929094794 bytes; elapsed=285s
FTP SIZE OK: 2.73 GB
FTP UPLOAD OK: ...tar.gz
FTP RETENTION OK: осталось=10
SUCCESS: ...
```

При ошибке потока перед штатным обработчиком записываются `STREAM tar stderr` и/или `STREAM curl stderr`, коды обоих процессов, число переданных байт и время. `tar=141` может быть следствием закрытия потока со стороны curl; смотрите оба кода. `tar=1` тоже считается ошибкой: архив не объявляется успешным. Причину устанавливайте по stderr, а не только по номеру строки.

Диагностика не меняет настройки таймаутов и не добавляет повторные попытки. Общего ограничения длительности FTP-загрузки нет. Временные stderr-файлы удаляются после переноса сообщений в основной лог. Для логов настройте ротацию средствами сервера.

## Ограничения и Git

Используется обычный `ftp://`, без шифрования. Доступ к FTP должен предоставляться доверенным способом. Поддержка FTPS/SFTP требует отдельной доработки.

Передача и совпадение размера не заменяют пробное восстановление. Дамп использует `--single-transaction`: это не гарантирует согласованность изменяемых MyISAM-таблиц; файлы сайта и база также не являются единым атомарным снимком. Скрипт не сохраняет конфигурацию веб-сервера, PHP, cron, сертификаты и настройки почты за пределами корня сайта.

Не коммитьте рабочий `backup.conf`, `.msmtprc`, дампы и архивы. Сам архив сайта может содержать пароли подключения к БД в настройках CMS. `.gitignore` не удаляет секреты, уже попавшие в историю Git. В пакете оставлены только примерные реквизиты конфигурации; домен и адреса уведомлений в скрипте не являются паролями.

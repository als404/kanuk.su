# Bitrix24 CRM: совместимость экспорта заказов с MySQL 8.4

**Сайт:** `discount-tools.ru`  
**Дата исправления:** 31 октября 2026 г.  
**Платформа:** 1С-Битрикс (ядро 17.5.8), PHP 7.4, MySQL 8.4  
**Статус:** исправление внедрено и проверено на production

## Проблема

После миграции сайта на MySQL 8.4 обмен заказами с облачным Битрикс24 перестал корректно обрабатывать первый заказ, доступный для выгрузки. При экспорте заказа **№2005**, позиция корзины **№11150**, выполнение прерывалось при вызове `CSaleBasket::GetPropsList()`. Клиент Битрикс24 сообщал об ошибке обработки ответа сервера (`[XL1]` и сопутствующие сообщения).

Экспортёр формировал запрос следующего вида:

```sql
SELECT DISTINCT BP.NAME AS NAME, BP.VALUE AS VALUE, BP.CODE AS CODE
FROM b_sale_basket_props BP
WHERE BP.BASKET_ID = 11150
ORDER BY BP.SORT ASC, BP.ID ASC
```

При `SELECT DISTINCT` используемые в `ORDER BY` поля `BP.SORT` и `BP.ID` должны присутствовать в списке выбираемых выражений. Старый код Битрикс не включал их в `SELECT`, что несовместимо с MySQL 8.4.

## Исправление

**Production-файл:**

```text
/var/www/discount-tools/public/bitrix/modules/sale/general/export.php
```

В функции `CSaleExport::getXmlBasketItems()` (на production после удаления диагностики — строка около **1304**) изменяется **только** список полей последнего аргумента `CSaleBasket::GetPropsList()`:

**Было:**

```php
$dbProp = CSaleBasket::GetPropsList(Array("SORT" => "ASC", "ID" => "ASC"), Array("BASKET_ID" => $arBasket["ID"]), false, false, array("NAME", "VALUE", "CODE"));
```

**Стало:**

```php
$dbProp = CSaleBasket::GetPropsList(Array("SORT" => "ASC", "ID" => "ASC"), Array("BASKET_ID" => $arBasket["ID"]), false, false, array("NAME", "VALUE", "CODE", "SORT", "ID"));
```

Патч: [`patches/sale-export-distinct-order-by.patch`](patches/sale-export-distinct-order-by.patch). Важно: добавление `ID` может влиять на семантику `DISTINCT` для строк с одинаковыми `NAME`, `VALUE` и `CODE`. Для проверенного обмена это изменение работает; при обновлении ядра следует перепроверить соответствующий запрос.

## Подтверждение результата

31.10.2026 в **17:22** журнал PHP показал успешное завершение операций:

```text
B24_PROPS_4 QUERY_RETURNED
B24_BASKET_6 ITEMS_DONE
B24_STAGE_7 XML_WRITTEN ID=2005
B24_EXPORT_RETURN ORDERS=1
```

После исправления Битрикс24 завершил загрузку, а в CRM появилась сделка **EShop #2005** на **1 654 руб.** с соответствующей товарной позицией. После удаления временной диагностики автоматические запросы `checkauth`, `init`, `query` (17:31–17:32) снова возвращали HTTP 200; ответ пустой выгрузки `query` имел прежний размер **207–208 байт**.

Это подтверждает восстановление экспорта заказа №2005; будущие обмены следует контролировать по факту появления новых заказов в CRM, поскольку HTTP 200 само по себе не подтверждает их импорт.

## Сопутствующие замечания

- Временные диагностические изменения из `component.php`, `export.php`, `basket.php` были удалены. Остаётся только изменение аргумента `GetPropsList()`.
- Контакт «Технический для купить в 1 клик» — ранее существовавшая схема оформления заказов через компонент покупки в один клик; к исправленному SQL не относится.
- При обновлении ядра Битрикс `export.php` может быть заменён. Проверить наличие патча обязательно.
- Не отключать строгие SQL-режимы MySQL и не изменять данные заказов ради этого исправления.

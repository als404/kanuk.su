# Миграция сайта: проверка патча экспорта Битрикс24

Документ предназначен для переноса `discount-tools.ru` на новый сервер/хостинг, включая возможную смену домена, и для обновлений ядра Битрикс.

## 1. Назначение

Файл `bitrix/modules/sale/general/export.php` в версии ядра Битрикс, установленной на 31.10.2026, содержит несовместимый с MySQL 8.4 вызов `CSaleBasket::GetPropsList()`. Патч добавляет в выбираемые поля `SORT` и `ID`, уже присутствующие в сортировке SQL.

Репозиторий хранит **патч**, но не целиком модифицированный файл ядра. Файл на сайте должен соответствовать версии Битрикс, для которой этот патч подготовлен.

## 2. Перед применением

- Сделать резервную копию файлов сайта и базы данных штатной процедурой миграции.
- Проверить, что миграция завершена и файл `bitrix/modules/sale/general/export.php` существует.
- Проверить, не сохранено ли исправление при копировании файлов с предыдущего сервера.
- Не применять патч повторно к уже исправленному файлу.

Путь production на 31.10.2026:

```bash
SITE=/var/www/discount-tools/public
TARGET="$SITE/bitrix/modules/sale/general/export.php"
```

На другом хостинге **заменить `SITE` на фактический DOCUMENT_ROOT**. Путь к репозиторию в примерах далее задаётся отдельно:

```bash
REPO=/path/to/your/git/repository
PATCH_FILE="$REPO/src/modules/bitrix24-sale-export-mysql8/patches/sale-export-distinct-order-by.patch"
```

## 3. Проверка наличия исправления

```bash
sudo grep -nF 'array("NAME", "VALUE", "CODE", "SORT", "ID")' "$TARGET"
```

Если строка найдена в вызове `CSaleBasket::GetPropsList()` внутри `getXmlBasketItems()`, исправление **уже присутствует**: применять патч не требуется.

Если строка отсутствует, убедиться, что исходный вызов всё ещё совпадает с тем, что указан в README. Для другой версии ядра патч может потребовать адаптации.

## 4. Применение на сервере, где исправления нет

Сначала выполнить сухую проверку:

```bash
sudo patch --dry-run -p1 -d "$SITE" < "$PATCH_FILE"
```

**Если проверка не прошла — остановиться.** Не применять патч с принудительным выбором смещений и не перезаписывать файл вслепую. Сравнить код с README и версией установленного Битрикс.

Если сухая проверка прошла, сохранить исходный файл и применить:

```bash
sudo cp -a "$TARGET" "$TARGET.before-mysql8-fix"
sudo patch --batch -p1 -d "$SITE" < "$PATCH_FILE"
```

Проверить единственное ожидаемое изменение, синтаксис и отсутствие временной диагностики:

```bash
sudo diff -u "$TARGET.before-mysql8-fix" "$TARGET" || true
sudo /opt/remi/php74/root/usr/bin/php -l "$TARGET"
sudo grep -nF 'array("NAME", "VALUE", "CODE", "SORT", "ID")' "$TARGET"
```

`php -l` в старом коде может сообщать предупреждения о `continue` внутри `switch`; критерием успешной синтаксической проверки является строка `No syntax errors detected`. На другом сервере заменить путь к PHP CLI на установленный.

## 5. Проверка после миграции

1. В Битрикс24 запустить штатный обмен заказами и убедиться, что он сообщает об успешной загрузке.
2. На сайте проверить логи запросов `checkauth`, `init`, `query` к `/bitrix/admin/1c_exchange.php` (без публикации полного URL: он содержит параметры сессии).
3. Проверить **фактическое появление новой сделки/заказа** в CRM или обновление существующего — HTTP 200 сам по себе недостаточен.
4. Проверить, что в файлах ядра нет временных отладочных маркеров `B24_STAGE_`, `B24_BASKET_`, `B24_PROPS_`.

Ранее обнаруженные ошибки были связаны с экспортом заказа №2005, позиция корзины №11150. После устранения несовместимости заказ успешно выгрузился.

## 6. Откат

Если патч только что применён и возникли ошибки, восстановить **только** сохранённую копию `export.php`:

```bash
sudo cp -a "$TARGET.before-mysql8-fix" "$TARGET"
sudo /opt/remi/php74/root/usr/bin/php -l "$TARGET"
```

Откат вновь возвращает исходное несовместимое поведение для MySQL 8.4, поэтому использовать его только как аварийную меру с последующей диагностикой.

## 7. При обновлении Битрикс и смене домена

- После обновления ядра проверить наличие исправленного вызова и, если он изменился, актуализировать патч. Не применять старый патч автоматически к новой версии.
- Смена домена сама по себе на SQL-исправление не влияет. Однако в Битрикс24 отдельно проверить адрес интернет-магазина/обмена, доступность HTTPS, авторизацию технического пользователя обмена и настройки интеграции.
- Убедиться, что конфигурация нового окружения (PHP, MySQL, права на файлы) соответствует перенесённому сайту. Не копировать значения путей из этого документа без адаптации.

## 8. Git

После копирования папки `src/modules/bitrix24-sale-export-mysql8/` в локальный репозиторий:

```bash
git add src/modules/bitrix24-sale-export-mysql8/
git commit -m "fix(bitrix): preserve MySQL 8.4 CRM order export compatibility patch"
```

Коммит сохраняет **исходники патча и инструкцию**, но сам по себе не изменяет production. На текущем production исправление уже установлено и было проверено 31.10.2026.

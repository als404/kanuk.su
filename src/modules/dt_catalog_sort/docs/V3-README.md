# Сортировка каталога — тестовая версия V3 (247)

**Среда:** Bitrix 17.5.8, PHP 7.4, инфоблок 16, тестовый сервер `discount-tools-test` (192.168.15.247). Код для `src/modules/dt_catalog_sort/` в Git. На production не применять.

## Подтверждённое исходное состояние

- `DT_SORT_GROUP` (ID 692), `DT_SORT_PRICE` (ID 693) заполнены у всех 6074 активных товаров. Контроль: `MISSING=0`, `GROUP_MISMATCH=0`.
- Группы: товары с ценой — BREXIT 10, ESSON 20, остальные 30; без цены — BREXIT 40, ESSON 50, остальные 60.
- В режиме `HIDE_NOT_AVAILABLE=L` недоступные товары выводятся в конце. Активных SKU на тестовой базе не найдено.
- Старый `section.php` использует `DT_SORT_GROUP` везде, поэтому кнопка «Цене» не даёт общей сортировки.

## Что меняется

1. Создаётся одно новое **числовое одиночное** свойство `DT_SORT_ZERO` инфоблока 16. `0` означает положительную итоговую цену, `1` — нулевую / отсутствующую. `DT_SORT_GROUP` и `DT_SORT_PRICE` остаются без изменения.
2. Обновлённый CLI-скрипт при `--rebuild` вычисляет и поддерживает сразу 3 свойства. Не пересчитывать «По цене» через `MINIMUM_PRICE`: там базовая цена без скидки.
3. `section.php` переключает поля в зависимости от кнопки:

| Режим | Поле 1 | Поле 2 | HIDE_NOT_AVAILABLE |
|---|---|---|---|
| По умолчанию | DT_SORT_GROUP ASC | DT_SORT_PRICE ASC | L |
| Цене | DT_SORT_ZERO ASC | DT_SORT_PRICE ASC/DESC | N |
| Рейтингу | DT_SORT_GROUP ASC | rating ASC/DESC | L |

При сортировке «Цене» **нет** приоритета наличия / производителя: все товары с положительной ценой идут по цене, товары без цены — в конце при ASC и DESC. «По умолчанию» фиксирован по возрастанию цены внутри групп. Рейтинг пока остаётся внутри групп. Параметр `N` не скрывает недоступные товары, а помещает их в общий список.

## Рекомендуемая последовательность

1. На тестовом 247 сделать backup текущего `dt_catalog_sort.php` и `section.php` (последний менять только после заполнения DT_SORT_ZERO). Размещать и менять PHP через VSCode.
2. Заменить файл скрипта из пакета и выполнить только read-only:

```bash
PHP=/opt/remi/php74/root/usr/bin/php
TOOL=/var/www/discount-tools/tools/dt_catalog_sort.php
$PHP -l "$TOOL"
$PHP "$TOOL" --create-properties
$PHP "$TOOL" --preview --ids=1980,1981,1987,1997,2005,2067,11797
```

Ожидается `WOULD_CREATE DT_SORT_ZERO (type=N, single)`; в preview `ZERO=1` для 1980,1987,1997; `ZERO=0` для 1981,2005,2067,11797. `WRITES=0`.

3. После проверки наличия backup тестовой БД: `$PHP "$TOOL" --create-properties --apply --confirm=test`; затем `$PHP "$TOOL" --check-properties`. ВНИМАНИЕ: property ID назначит Bitrix.
4. Контрольная запись выборки (режим `--rebuild` затрагивает все 3 свойства):

```bash
$PHP "$TOOL" --rebuild --ids=1980,1981,1987,1997,2005,2067,11797 --apply --confirm=test
```

5. Убедиться чтением `CIBlockElement::GetProperty`, что ZERO=0/1 сохранён. Затем массовое пакетное заполнение всех активных элементов инфоблока 16, **начиная с `--after=0`**, не с устаревшей контрольной точки.
6. Проверить TOTAL=FILLED, пропуски, несоответствия: ZERO=1 тогда и только тогда, когда DT_SORT_PRICE<=0. Использовать новую контрольную точку v3.
7. Только после этого в `section.php`: заменить `//SORT//` блок на `section-sort-replacement-v3.php.inc`, вставить переменные перед `//SECTION//` из `section-variables-v3.php.inc`, заменить 4 `ELEMENT_SORT_*` и именно строку `HIDE_NOT_AVAILABLE` внутри вызова `bitrix:catalog.section` по третьему фрагменту. Не менять другие вхождения `HIDE_NOT_AVAILABLE`.
8. Проверить `php -l`, diff к backup, браузер: default, price ASC, price DESC, rating, 24/48 и границы пагинации.

## Безопасность и ограничения

- Скрипт разрешает запись только когда hostname `discount-tools-test` и флаги `--apply --confirm=test`; иначе ошибка. Для запуска необходим рабочий prolog Bitrix.
- В DB обновляются только новые сортировочные свойства; базовые цены, существующие скидки, `MINIMUM_PRICE`, `rating` и `CATALOG_SORT_PRIORITY` не меняются.
- Исходные файлы сайта могли быть в CP1251: примеры фрагментов состоят из ASCII; сохранить исходную кодировку `section.php` при редактировании.
- Стоимость рассчитывается для стандартной группы №2, без купонов, с учётом действующих скидок на момент расчёта. Автоматического обновления при изменении цены, правил скидок, статуса акции ещё нет. До production обязательно реализовать.
- При равной цене/рейтинге штатные два поля не гарантируют стабильной вторичной сортировки по ID. До release проверить границы страниц.
- После перезаписи `section.php` проверить локальный/композитный кеш, не очищая его без диагностики.

# V4.4 — адресная очистка кеша при пересчёте сортировки (только test 247)

## Задача

В V4.2 `DT_SORT_GROUP`, `DT_SORT_PRICE`, `DT_SORT_ZERO` пересчитываются, но после выполнения worker композитные HTML-файлы каталога остаются. Простого `ClearByTag('iblock_id_16')` недостаточно для заранее сгенерированных HTML. Также V4.2 удаляет запись очереди **до** общей инвалидации, поэтому сбой очистки потенциально теряет необходимость повтора.

V4.4:

- сохраняет действующие расчёты, события и SQL-очередь;
- после обработки элемента очищает тегированный кеш Битрикс и `index@*.html` **только** в корне каталога, разделах/родителях и карточках затронутого товара;
- учитывает иерархические и плоские пути, дополнительные привязки товара к разделам, различные варианты `index@view=...`, `index@PAGEN_...`;
- подтверждает успешную очистку **до** `DELETE ... WHERE VERSION=...` из очереди; при ошибке задание остаётся в очереди, даже если индекс уже обновлён;
- добавляет `--cache-preview --ids=...` для проверки путей/прав без записи;
- ограничивает удаления хостом `discount-tools-test`, каталогом `/bitrix/html_pages/vmtest.discount-tools.ru/catalog`, именами `index@*.html`, максимум 256 каталогов и 5000 файлов за один товар;
- при активном sweep (`--sweep>0`), если индекс изменился, но очистка провалилась, дополнительно ставит ID в очередь с причиной `cache-retry`;
- для ручного CLI `--recalc` также выполняет инвалидацию.

**Не входит в V4.4:** переработка `cost_update`, `dealer_export`, автоматическое расписание скидок, включение Google Sheets на тесте, перенос на production, удаление всех кешей сайта.

## Исходная база

Патч подготовлен **из V4.2** (`dt_catalog_sort_auto_v4_2_test247.zip`). Продуктовый Git-архив `kanuk.su-master.zip` не содержит `src/modules/dt_catalog_sort`, поэтому все исходники модуля включены в данный ZIP, с расположением `src/modules/dt_catalog_sort/` для отдельного Git-репозитория. Другие модули из Git не изменены.

## Проверенные пути на 247

- `DOCUMENT_ROOT=/var/www/discount-tools/public`
- композит: `/var/www/discount-tools/public/bitrix/html_pages/vmtest.discount-tools.ru/catalog`
- наличие `index@.html`, `index@view=price.html`, `index@view=list.html`, `index@view=table.html`;
- 33 файла на момент диагностики;
- каталог имеет владельца/группу `discount:discount`, режим `775`.

Из этого **нельзя** вывести право пользователя `als` удалять файлы: проверить `id -nG als`. Если `discount` не входит в список и нет иной ACL, остановиться, не применять `chmod -R` и не переводить cron на root.

## Развёртывание (только после проверки прав)

1. Проверить `id -nG als`, `crontab -l`, `stat` файлов на сервере 247.
2. Сохранить файл cron и сделать резервные копии **двух заменяемых** PHP-файлов (допустим, в `/home/als/backups/`, за пределами DOCUMENT_ROOT); сохранить права/владельцев.
3. На время установки закомментировать **только** строку cron сортировки через `EDITOR=vi crontab -e`.
4. Через VSCode: сначала создать `DtCatalogSortCache.php`, затем заменить `DtCatalogSortAuto.php` и CLI. Сохранить ожидаемую кодировку и короткие `<?`.
5. Проверить синтаксис:

   ```bash
   PHP=/opt/remi/php74/root/usr/bin/php
   LIB=/var/www/discount-tools/public/local/php_interface/dt_catalog_sort
   TOOL=/var/www/discount-tools/tools/dt_catalog_sort_auto.php
   $PHP -d short_open_tag=On -l "$LIB/DtCatalogSortCache.php"
   $PHP -d short_open_tag=On -l "$LIB/DtCatalogSortAuto.php"
   $PHP -d short_open_tag=On -l "$TOOL"
   ```

6. Выполнить только чтение:

   ```bash
   $PHP "$TOOL" --cache-preview --ids=5238
   $PHP "$TOOL" --preview --ids=5238
   $PHP "$TOOL" --status
   ```

   В `CACHE_PREVIEW` проверить `paths`, `cached_files`, `unwritable_dirs` (должен быть пустой массив). При пустом `paths` или ненулевом `unwritable_dirs` **не запускать** рабочую обработку.

7. Контролируемый тест очистки **без изменения цены** (после бэкапа и предварительного просмотра):

   ```bash
   $PHP "$TOOL" --enqueue --ids=5238 --apply --confirm=test
   $PHP "$TOOL" --run --queue=1 --sweep=0 --apply --confirm=test
   $PHP "$TOOL" --status
   $PHP "$TOOL" --cache-preview --ids=5238
   ```

   В успешном запуске: `QUEUE.selected=1`, `QUEUE.failed=0`, `STATUS.queued=0`; `QUEUE.changed=0` допустим, поскольку индекс уже актуален. `cache_deleted` показывает число удалённых HTML-файлов, которое может равняться нулю, если кеш не был сформирован.

8. Проверить страницы каталога в браузере; затем вернуть строку cron сортировки в исходное положение через `EDITOR=vi crontab -e`.

При проверке изменения цены через админку Битрикс можно дополнительно подтвердить `QUEUE.changed=1` и удаление файлов соответствующих разделов. Без предварительной проверки вывода `--cache-preview` этот шаг не выполнять.

## Откат

1. Остановить **только** cron сортировки.
2. Восстановить из резервных копий V4.2 `DtCatalogSortAuto.php` и `dt_catalog_sort_auto.php`.
3. Оставить новый `DtCatalogSortCache.php` неиспользуемым либо удалить только его после проверки отсутствия ссылок.
4. Проверить синтаксис и `--status`, затем включить cron.

Данные сортировки и служебные таблицы не удаляются. Если композитные HTML-файлы уже очищены, они создадутся снова при обращении к сайту.

## Ограничения и предосторожности

- Обработчик основан на маршрутах текущего каталога; для иных слугов кроме латинских, цифр, `_` и `-` специально выбрасывает исключение, чтобы не удалять непроверенные пути. При такой ошибке очередь остаётся для диагностики.
- Удаление файлов в кеширующем каталоге не является атомарным относительно параллельной генерации страницы: после установки проверить фактическую сортировку в браузере.
- После удаления последнего экземпляра товара из БД его привязки к разделам могут быть недоступны; такой сценарий потребует отдельной политики инвалидации.
- Не запускать патч на production без повторной диагностики хоста, каталогов, прав, блокировок и адаптации тестовых ограничений в отдельном релизе.

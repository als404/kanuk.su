# dt.documents — техническая фиксация версии 0.1.2 и production-исправлений

Дата: 2026-11-10. Модуль по-прежнему объявляет `VERSION=0.1.2` — это **не новый номер версии**, а снимок исходников 0.1.2 с рабочими исправлениями.

## Реализовано и проверено

- Миграция таблиц: добавлено поле `MATCH_MODE`; существующая запись сертификата сохранилась в режиме `legacy`.
- Поиск по артикулу (`6002150`, маска `600205_`), производителю и их сочетанию; правила производитель/раздел и его подразделы.
- Исправление пагинации списка проверки товаров (`$dtdPreviewPage`, не конфликтует с административным прологом).
- Исправление URL верхних вкладок в `admin/list.php` (`lang=...`), чтобы не терялось меню «Контент».
- Перенос PHP-рендеринга из дочернего кэшируемого `catalog.element` в родительский `catalog/.default/element.php` после `IncludeComponent`; адаптер получает `$dtdPublicProductId` и перечитывает свойства инфоблока 16.
- Убрано пилотное ограничение на `ID=7938`; используется адаптер R3. Его SHA256 совпадает с сообщённым production-значением `75f31a885d43eece7e987f6a6cb6aa27e890f3f3d044b7c6c31634aeb4023882`.
- В `addition_include.js` предусмотрен пропуск JS-вывода при существующем `#addition-info.dt-documents`; пока старый JS остаётся резервным механизмом.
- Импортированы 48 старых документов. Последний список показывает 51 запись; загруженные PDF/изображения — отдельные эксплуатационные данные, в этот архив не включены.

## Что НЕ реализовано

- Автоматический целевой сброс композитного и компонентного кэша при правке документа.
- Полный вывод старого `db.js` из эксплуатации (скрипты ещё подключены в `/catalog/index.php`).
- Фильтр списка материалов по полю `ACTIVE` (Все / Да / Нет), включая объединение с прочими фильтрами и пагинацией.
- Кнопка «Редактировать» для материалов из проверки товара.
- Загрузка и **замена** автоматического паспорта и превью через админку (сейчас файлы попадают через SFTP).

## Файлы в архиве

- `src/modules/dt.documents/` — исходники модуля 0.1.2 R1 + pagination/nav hotfix + public adapter R3.
- `deploy/upload/doc/addition_include.js` — JS из проверенного пилотного пакета.
- `snippets/` — точные правки **существующих** `/catalog/index.php`, родительского `element.php`, и удаление устаревшей вставки из дочернего `template.php`.
- `docs/` — управленческий отчёт и инструкция для фиксации в Git.

## Контрольная проверка до Git

В архиве **нет полной текущей копии production** `/catalog/index.php` и двух `catalog.element`-шаблонов. Пользователь редактировал их через VSCode, и их реальные версии нужно сохранить в репозиторий отдельно с проверкой `git diff`; применять snippets поверх production без сверки не требуется. Также нельзя утверждать, что каждая копия модуля в этом архиве идентична установленной production-версии: архив собран из ранее проверенных релизных пакетов и hotfix, а не из live git diff.

Не включайте в репозиторий: `.settings.php`, пароли, SQL-дампы, `/bitrix/cache`, `/bitrix/html_pages`, пользовательские PDF/превью из `/upload/doc/dt_documents`, резервные копии, журналы.

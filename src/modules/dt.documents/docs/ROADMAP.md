## P1 — фильтр «Активен» в списке материалов

Сейчас `/bitrix/admin/dt_documents_list.php` фильтрует документы по категории (`type`) и названию (`q`), а статус `ACTIVE` лишь показывает в таблице.

- Добавить селектор **Активен:** «Все» (по умолчанию), «Да» (`Y`), «Нет» (`N`).
- Фильтровать таблицу по `dt_doc_document.ACTIVE` на уровне SQL, включая `COUNT(*)`; не скрывать строки только в браузере.
- Совмещать новый параметр с категорией, поиском по названию и количеством строк 10/20/50.
- Сохранять выбранный статус в URL пагинации и после действий «Включить», «Отключить»; при сужении выборки корректно ограничивать номер страницы.
- Проверить сценарии: все / активные / неактивные; сочетания фильтров; включение и отключение материала; пустая выборка; 3 страницы по 20 записей.
- Файлы для изменения: `src/modules/dt.documents/admin/list.php` и `src/modules/dt.documents/lib/Repository.php`.
- Не менять данные таблицы, не выполнять миграцию, не менять правила публичного показа.

## P1 — быстрый переход из проверки товара к материалу

- Напротив каждого материала из БД добавлять ссылку «Редактировать» (`dt_documents_edit.php?lang=ru&id=<ID>`).
- Для автоматической инструкции без записи в БД переход к редактированию документа не показывать.
- Дать возможность открыть привязки, удалить один артикул или полностью отключить материал, предварительно проверив общие привязки к другим товарам.

## P1 — загрузка и замена автоматической инструкции через админку

- Отдельный сценарий «Заменить инструкцию и превью» для товара (производитель + точный артикул).
- Загрузка PDF и JPG/PNG/WebP с проверкой формата, размера и прав доступа.
- Атомарная замена существующих файлов по правилам `/upload/doc/manual/` и превью, с резервной копией прежней версии и защитой от путевых коллизий.
- Не создавать вторую инструкцию как запись в таблице и не показывать две карточки вместо одной.
- Проверить доступность файлов через веб, обновление кэша и rollback.
- До реализации отдельно обследовать существующее формирование путей и названий файлов.

# dt.catalogproperties — перенос на другой хостинг или домен

## Перед переносом

1. Определить действительные `DOCUMENT_ROOT`, пути PHP CLI/PHP-FPM, режим выполнения PHP и параметры соединения с MySQL; не переносить значения тестового окружения (`kanuk_utf8`) в production автоматически.
2. Создать и проверить резервные копии файлов и БД; отдельно сохранить текущий `/bitrix/php_interface/init.php`.
3. Убедиться, что ID каталога — `16`, и проверить IDs разделов/свойств. Если IDs изменились, **до импорта настроек** составить соответствия; простое копирование таблиц привязок недопустимо.
4. Проверить содержимое и наличие миграционных SQL-файлов, обёртки административной страницы и актуального кода модуля в Git.
5. Убедиться, что PHP 7.4 и версия Битрикс совместимы с кодом модуля; на другом окружении провести отдельные тесты.

## Файлы и интеграция

Разместить файлы `src/modules/dt.catalogproperties/` в:

```text
<DOCUMENT_ROOT>/local/modules/dt.catalogproperties/
```

Если административная обёртка `deploy/bitrix/admin/dt_catalog_properties.php` присутствует в репозитории, установить её в:

```text
<DOCUMENT_ROOT>/bitrix/admin/dt_catalog_properties.php
```

**Обязательно проверить регистрацию обработчика** `main:OnAdminTabControlBegin` в `<DOCUMENT_ROOT>/bitrix/php_interface/init.php`:

- регистрация только для `iblock_element_edit.php` и `cat_product_edit.php`;
- загрузка файла `/local/modules/dt.catalogproperties/lib/AdminElementProperties.php`;
- обработчик `\DT\CatalogProperties\AdminElementProperties::onAdminTabControlBegin`;
- отсутствие двойной регистрации.

Не заменять весь `init.php` файлом с другого сервера: в нём могут находиться другие обработчики сайта. Переносить только проверенный фрагмент интеграции.

## База данных

Настройки наборов характеристик хранятся в:

- `dt_cp_section_config` — факт настройки раздела;
- `dt_cp_section_property` — связи и порядок свойств раздела.

При переносе с сохранением IDs переносить обе таблицы вместе с данными. При новой установке использовать `install/sql/001_create_tables.sql` **только после** проверки, что таблиц ещё нет и файл соответствует текущей версии модуля. **Не выполнять** `001_rollback_tables.sql` для «очистки» или повторной установки: он уничтожает конфигурацию наборов.

Для контроля — выполнить только чтение:

```sql
SELECT COUNT(*) FROM dt_cp_section_config;
SELECT COUNT(*) FROM dt_cp_section_property;
```

Сопоставить выбранные разделы/свойства с фактическими ID инфоблока 16.

## Проверки после развёртывания

1. Проверить синтаксис:

   ```bash
   php -l <DOCUMENT_ROOT>/local/modules/dt.catalogproperties/lib/AdminElementProperties.php
   ```

   Вместо `php` использовать фактический PHP CLI сайта. На текущем сервере это `/opt/remi/php74/root/usr/bin/php`.
2. Открыть `/bitrix/admin/dt_catalog_properties.php` и проверить назначения и порядок характеристик одной настроенной категории.
3. Открыть существующий товар обычным редактированием; убедиться, что видны его служебные и разрешённые характеристики, а не весь перечень технических свойств.
4. Открыть **копирование** товара в обоих интерфейсах (`iblock_element_edit.php?action=copy`, `cat_product_edit.php?action=copy`). Сохранение копии для проверки фильтрации не требуется. Раздел определяется по `ID` исходного товара, а не по `find_section_section`.
5. Проверить характеристику со значением, содержащим сущность (например, `1000&#215;680&#215;200`): в поле должно отображаться `1000×680×200`.
6. На контролируемом тестовом товаре проверить сохранение и повторное открытие такого значения; учитывать, что после сохранения в БД может оказаться символ `×` вместо исходной сущности.
7. Проверить журналы PHP только при возникновении ошибки; не включать временную диагностику на постоянной основе.

## Откат кода

- Для отката поведения административной формы восстановить предыдущую Git-версию `lib/AdminElementProperties.php` и проверить синтаксис и работу формы.
- Для полного отключения обработчика — убрать **только его** регистрацию из `init.php`, сохраняя остальные обработчики сайта.
- Не удалять рабочие таблицы `dt_cp_section_config` и `dt_cp_section_property` в рамках отката отображения/копирования: это независимые данные конфигурации.
- Полное удаление модуля/административной обёртки проводить только после резервного копирования и отдельного решения о сохранении настроек.

## Смена домена

Сама смена домена не требует изменения SQL-модели назначений свойств. Проверить новые пути, административную обёртку, интеграцию в `init.php` и доступность каталога модуля для PHP-FPM.

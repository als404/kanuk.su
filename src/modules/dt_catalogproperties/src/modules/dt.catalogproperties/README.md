# dt.catalogproperties — характеристики категорий каталога

**Окружение:** 1С-Битрикс 17.5.8, PHP 7.4, инфоблок каталога `16`. Рабочая установка: `discount-tools.ru`. Исторический стенд первоначального этапа: VM `192.168.15.247`.

## Назначение

Модуль управляет наборами характеристик категорий каталога:

- позволяет вручную назначать существующие свойства инфоблока категории и устанавливать их порядок;
- копирует **недостающие** свойства из непосредственного родительского раздела. Скопированный набор независим от последующих изменений родителя; повторное копирование не удаляет существующие связи;
- в административной форме товара показывает характеристики, настроенные для его основного раздела;
- поддерживает ту же фильтрацию при **копировании товара** (`action=copy`);
- корректно отображает HTML-сущности в значениях характеристик, не требуя массового исправления данных в БД.

Важное различие: «копировать недостающие свойства из родительского раздела» — операция настройки категории; `action=copy` — копирование **товара** в административной панели Битрикс.

## Управление наборами характеристик

1. Выбрать раздел каталога и назначить ему существующие свойства инфоблока 16.
2. Установить порядок свойств.
3. При необходимости выбрать «Скопировать недостающие из родителя». Команда добавляет отсутствующие свойства в конец списка, не удаляя уже настроенные.
4. Действие «Исключить» удаляет только связь свойства с категорией, **не значение свойства товара**.

«Категория без настройки» и «категория с настроенным пустым набором» различаются записью в `dt_cp_section_config`. Для корневых категорий копирование из родителя недоступно.

## Административная форма товара

Реализация: `src/modules/dt.catalogproperties/lib/AdminElementProperties.php`, обработчик `onAdminTabControlBegin()`.

Обработчик работает только с формой `form_element_16`:

- при обычном редактировании определяет основной раздел из `b_iblock_element.IBLOCK_SECTION_ID`;
- при копировании (`action=copy`) использует `ID` **исходного** товара для определения того же основного раздела; сохранение копии для фильтрации не требуется;
- при добавлении нового товара использует положительный `IBLOCK_SECTION_ID` из URL; если раздел неизвестен, не меняет форму;
- если для раздела нет настройки в `dt_cp_section_config`, оставляет форму неизменной;
- сохраняет служебные свойства `ARTNUMBER`, `MANUFACTURER`, `COUNTRY`, `GUARANTEE` и показывает настроенные характеристики;
- скрывает неразрешённые *технические* свойства с кодами вида `PROP123`, не удаляя поля из формы и не изменяя данные товаров;
- упорядочивает разрешённые технические свойства по `SORT_ORDER` из `dt_cp_section_property`.

Поддерживаются оба штатных административных интерфейса:

```text
/bitrix/admin/iblock_element_edit.php?IBLOCK_ID=16&ID=11814&action=copy
/bitrix/admin/cat_product_edit.php?IBLOCK_ID=16&ID=12080&action=copy
```

Параметр `find_section_section` — контекст списка, а не надёжный источник основной категории товара.

### Отображение HTML-сущностей

При наличии в БД текста `1000&#215;680&#215;200` Битрикс может формировать поле ввода с HTML-атрибутом `value="1000&amp;#215;680&amp;#215;200"`. В браузере код `&#215;` тогда отображается буквально.

Обработчик формы **универсально для видимых характеристик** восстанавливает допустимые числовые десятичные/шестнадцатеричные и именованные HTML-сущности на уровне HTML-представления поля. Например:

| Значение в БД | Отображение в форме |
| --- | --- |
| `1000&#215;680&#215;200` | `1000×680×200` |
| `Труба &#216; 20` | `Труба Ø 20` |
| `90&deg;` | `90°` |

Неизвестные сущности остаются без изменений. Весь HTML формы целиком не декодируется; для обработки используются только подходящие поля характеристик. При сохранении отредактированного значения может быть записан уже сам UTF-8-символ вместо исходной сущности — это ожидаемо.

## Проверки, выполненные на production (05.11.2026)

- При копировании товара через `cat_product_edit.php` и `iblock_element_edit.php` отображаются характеристики исходной категории вместо всех 500+ свойств.
- HTML-сущности в проверенных полях габаритов отображаются как символы `×`.
- После сохранения и повторного открытия товара символ отображается корректно.
- `php -l` для `AdminElementProperties.php`: ошибок синтаксиса нет.

Это функциональная проверка конкретных сценариев, а не гарантия отсутствия проблем для всех типов свойств.

## Безопасность и ограничения

- Настройка наборов предназначена для администратора (`IsAdmin()`), изменяющие действия страницы должны проверять `check_bitrix_sessid()`.
- IDs разделов/свойств проверяются на принадлежность нужному инфоблоку в логике настройки.
- Обработчик формы читает основной раздел товара из БД, но не изменяет значения характеристик напрямую.
- Изменения текущего этапа выполнены в локальном модуле; ядро `/bitrix/modules/` не редактируется.
- Копирование характеристик между категориями не синхронизирует наборы задним числом.
- Товары без основного раздела и сценарии с несколькими разделами требуют отдельной проверки.
- Публичное отображение товаров и другие обработчики модуля не входят в объём описанной здесь проверки административной формы.

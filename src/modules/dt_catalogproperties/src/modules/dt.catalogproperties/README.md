# dt.catalogproperties

Локальный модуль управления наборами характеристик категорий каталога **инфоблока №16** для Битрикс 17.5.8 / PHP 7.4. Источник: проверенная тестовая VM 247, состояние на 24.10.2026. Документация актуализирована после проверки массового заполнения и сохранения через редактор магазина.

## Возможности

- Ручное назначение технических свойств `PROP[0-9]+` категориям, изменение порядка, исключение без удаления значений товаров.
- Копирование **недостающих** свойств из непосредственного родителя; копия не является динамическим наследованием.
- Ненастроенная категория: штатный набор характеристик; настроенная пустая категория: пустой технический набор.
- В карточке товара для настроенной категории CSS-скрытие лишних технических полей и перестановка разрешённых по `SORT_ORDER`. Поля остаются в HTML/POST для сохранности данных. Не является оптимизацией формирования 565 полей на сервере.
- Публичная карточка использует набор категории и версионирование кеша; при сохранении правил предусмотрена адресная очистка composite HTML кеша.
- Пункт меню **Магазин → Продукция → Характеристики категорий**, сразу после «Свойства товаров».

## Установка на новую копию сайта

1. Проверить резервную копию БД и файлов. Сохранить текущие три файла шаблонов; **не заменять шаблоны целиком без сравнения diff**. Проверить идентификаторы инфоблока, разделов и свойств.
2. Разместить каталог `src/modules/dt.catalogproperties` как `<DOCUMENT_ROOT>/local/modules/dt.catalogproperties`.
3. При чистой базе создать таблицы SQL из `001_create_tables.sql`, затем **однократно** выполнить `002_add_config_version.sql`. При переносе существующей базы с этими таблицами **не выполнять** миграции повторно. Таблицы с реальными назначениями надо переносить вместе с данными.
4. Установить модуль стандартно в админке Битрикс **Настройки → Настройки продукта → Модули** (проверить фактическое название раздела для версии). Установщик автоматически создаёт wrapper в `/bitrix/admin/` и регистрирует `OnAdminTabControlBegin` и `OnBuildGlobalMenu` с сортировкой `10000`. **SQL не выполняется установщиком автоматически**, поскольку требуется защитить имеющуюся конфигурацию.
5. На сервере с прежним ручным подключением удалить **только два блока** `DT Catalog Properties` в действующем `/bitrix/php_interface/init.php` **после успешной установки**. Иначе обработчики будут зарегистрированы дважды. Не удалять другую логику `init.php`.
6. Сравнить и точечно перенести интеграцию из `src/site/local/templates/...` (см. MIGRATION.md). После этого проверить меню, конфигурацию, карточки товаров и публичные страницы.

## Проверка поставки

Синтаксис всех PHP-файлов релиза проверен в среде сборки с PHP 8.4 и `short_open_tag=1`. Это **не заменяет** функциональную проверку на серверном PHP 7.4/Битрикс 17.5.8. В файле шаблона `template.php` используются короткие теги `<?`, поэтому при локальной диагностике нужно включить `short_open_tag=1`. Сам установщик и новая регистрация событий на VM 247 **пока не проходили функциональный тест**.

## Сохранение конфигураций из БД

При переносе или резервировании обязательно выгрузить **данные** таблиц `dt_cp_section_config` и `dt_cp_section_property`: Git хранит схему и код, а не реальные назначения. В дамп не включать тестовые товары и аудитные таблицы.

## Ограничения

- Константы `IBLOCK_ID=16` и пункт меню `menu_catalog_attributes_16` рассчитаны на существующие ID. При перенумерации требуется сопоставление **всех** зависимых ID, а не только замена константы.
- Формирование формы редактирования товара в Bitrix остаётся тяжёлым: скрытие полей визуальное, а не серверная оптимизация.
- Изменение категории в карточке товара требует сохранения и повторного открытия; для `action=copy` обработчик не применяется.
- **Адресная очистка composite кеша сейчас заблокирована для production**: в `CompositeCache::invalidateSection()` разрешён лишь `vmtest.discount-tools.ru`. На другом домене настройки сохранятся, но очистка выдаст предупреждение. До production необходимо отдельно протестировать смену хоста, URL-схему и выборочную очистку и только после этого снять ограничение.
- Установщик не меняет `init.php`, не перезаписывает существующий отличающийся wrapper, не удаляет таблицы при деинсталляции.
- Контроль доступа к странице: `$USER->IsAdmin()`; POST защищён `check_bitrix_sessid()`.

## Известные ограничения / отложенный аудит

- Отрицательный сценарий создания нового заказа, конкурентное оформление последней единицы несколькими покупателями и SKU не подтверждены практическими тестами. Серверная проверка не является механизмом атомарного резервирования.
- Нулевой остаток непосредственно в filtered и снятые с производства аксессуары не проверены отдельно; фактических связей аксессуаров с отмеченными товарами не было. Не все окна ошибок визуально проверены. Валидный POST сравнения и отдельный тест срока подписи не подтверждены.
- При естественном переходе остатка к нулю UI после импорта ещё не проверен. cost_update удаляет только известные каталожные HTML-пути; рекомендации на других страницах могут оставаться устаревшими. Прямой SQL обходит события Битрикс; очередь пишется после обработки бренда, ошибки unlink подавляются. Эти риски выделены для отдельного аудита.
- PROPS согласован в быстром поиске; в остальных шаблонах возможен старый формат со сжатием, несовместимый с add2basket.php. Не все сторонние вызывающие JS-коды проверены на JSON SUCCESS. Общий endpoint принимает REQUEST и десериализует клиентские параметры без классов, но явных проверок POST/sessid и строгой схемы свойств в нём нет. Не считать его полностью защищённым; требуется отдельный аудит и регрессия.
- Сторонние формы Demis Group/Altop и механизм dt.forms — отдельная разработка. В рамках данной задачи изменялось отображение кнопок, не внутренности форм.
- Rollback исторической миграции практически не испытан. При переносе обязательно проверить восстановление на тестовой копии.

# cost_update — синхронизация цен и остатков (PHP 7.4)

Модуль сайта на **1С-Битрикс** для обновления цен и остатков товаров инфоблока **16**:

- **Автоматически:** из Google Sheets для BREXIT и ESSON через `cron.php`.
- **Вручную:** импорт CSV для **любого активного бренда** из инфоблока **14** через защищённую страницу `index.php`.

Функции проверены на тестовом сайте `kanuk.brexit.by` с базой UTF-8: DRY-RUN, запись цен и остатков, отображение изменений на сайте, восстановление значений из Google Sheets и запуск по cron. **Это не заменяет проверку после переноса на `discount-tools.ru`.** Перед переносом и первым применением на новом сервере создайте резервные копии файлов и базы.

Подробная инструкция по переносу, замене домена, настройке Google Sheets (`spreadsheet_id`/`gid`) и добавлению автоматических брендов — в [MIGRATION.md](MIGRATION.md).

## Структура и назначение

| Путь | Назначение |
| --- | --- |
| `config.php` | Параметры БД/каталога, домен HTML-кэша, Google Sheets и конфигурация автоматических брендов |
| `cron.php` | Автоматическая синхронизация; по умолчанию проверка без записи, `--apply` — обновление БД |
| `index.php` | Административная форма ручной загрузки CSV |
| `lib/` | Обработка данных, запись изменений, блокировка и очистка кэша |
| `runtime/` | Логи, блокировка и очередь очистки кэша; требуется запись для PHP-FPM и cron |

## Автоматическая синхронизация Google Sheets

Настройки находятся в `local/modules/cost_update/config.php`:

- `spreadsheet_id` — ID книги Google Sheets из URL между `/d/` и `/edit`.
- `brands` → `BREXIT` / `ESSON` → `gid` — ID соответствующего листа из параметра `gid=` в URL.
- Столбцы BREXIT: **C** — артикул, **AV** — цена, **AW** — остаток. Столбец **AX** (другой склад) не учитывается.
- Столбцы ESSON: **C** — артикул, **L** — цена, **M** — остаток.

В текущей реализации для автоматических брендов используется **один общий `spreadsheet_id`**. Добавление нового бренда для cron требует его настройки в массиве `brands`, корректного `gid`, индексов столбцов и проверки DRY-RUN. Если таблица расположена в *другой книге*, загрузчик нужно доработать. **Не добавляйте все бренды сайта в `brands`: ручной CSV берёт список отдельно из инфоблока 14.**

## Ручной CSV-импорт

Страница администратора:

`/local/modules/cost_update/index.php`

Выберите бренд и загрузите CSV, подготовленный в Excel. Разделитель — **точка с запятой**; порядок полей:

```csv
артикул;стоимость;количество
2100156;12159;5
2100157;13500;
2100158;;0
```

- Пустая **цена** не изменяет цену товара.
- Пустое или отсутствующее **количество** не изменяет остаток.
- `0` в количестве означает нулевой остаток, **если включено** «Учитывать остатки».
- Если «Учитывать остатки» выключено, третья колонка игнорируется.
- Без галочки **«Выполнить запись в MySQL»** запускается DRY-RUN, без изменения данных.
- Поиск товара ограничен артикулом и выбранным брендом; неоднозначные соответствия не должны обновляться автоматически.

Все **активные бренды** подгружаются из инфоблока 14; добавлять их в `config.php` ради *ручного* импорта не нужно. Страница доступна только администратору Битрикс (доступ проверен на тестовом сайте).

## Запуск и расписание cron

На проверенном тестовом сервере используется PHP **7.4** по пути `/opt/php74/bin/php`. На новом хостинге уточните путь к CLI PHP 7.4 и корню сайта.

Запуск **без записи**:

```bash
cd /ПУТЬ_К_САЙТУ
/ПУТЬ_К_PHP74/php local/modules/cost_update/cron.php
```

Запуск **с записью** после проверки отчёта:

```bash
cd /ПУТЬ_К_САЙТУ
/ПУТЬ_К_PHP74/php local/modules/cost_update/cron.php --apply
```

Расписание: **каждый час с 07:00 до 22:00 включительно**, по часовому поясу сервера:

```cron
0 7-22 * * * cd /ПУТЬ_К_САЙТУ && /ПУТЬ_К_PHP74/php local/modules/cost_update/cron.php --apply >> local/modules/cost_update/runtime/cron.log 2>&1
```

Если сервер использует UTC, а нужно **07:00–22:00 по Москве (UTC+3)**, расписание для UTC-сервера — `0 4-19 * * *`. Не создавайте дублирующие задания. Планировщик должен работать от пользователя сайта, имеющего доступ к `runtime/` (на тестовом сервере — `kanuk`).

## Проверки после переноса

1. Проверить `document_root` и `html_cache_domain` в `config.php` (`discount-tools.ru`), путь реального HTML-кэша и Google `spreadsheet_id`/`gid`. БД переносится с тестового сайта UTF-8; проверить настройки соединения.
2. Проверить PHP 7.4 и расширения `pdo_mysql`, `mbstring`, `iconv`, а также доступ к HTTPS-экспорту Google Sheets (`allow_url_fopen` либо соответствующая реализация загрузчика).
3. Проверить `price_group_id` (для тестовой БД подтверждена группа **1**), свойство артикула **51**, индекс бренда **FACET_ID=104** в `b_iblock_16_index` и привязку к инфоблоку брендов **14**. `FACET_ID=104` — **не** `b_iblock_property.ID`.
4. Проверить владельца и права записи для `runtime/`, прежде всего `sync.lock`, `sync.log`, `cron.log`, `pending_cache.json`. На тестовом сервере файлы, созданные от `root`, вызывали `Permission denied` при запуске от `kanuk`.
5. Выполнить DRY-RUN cron, проверить объём изменений; затем контролируемый `--apply` и журнал. Проверить ручную форму, права администратора, изменение цены/остатка в карточке и каталоге, автоматическую очистку кэша.
6. Убедиться, что cron реально срабатывает в запланированное время, а не только при ручном запуске.

## Особенности и ограничения

- Изменяются только **существующие** записи `b_catalog_price`; создание отсутствующей цены не реализовано. Для тестовой базы подтверждён тип цены `price_group_id = 1`.
- Обновляются `QUANTITY` и `AVAILABLE`; при использовании складского учёта, резервов, торговых предложений, других правил доступности и дополнительных индексов может потребоваться адаптация.
- Пустые значения не перезаписывают поля; нулевой остаток является допустимым изменением. Некорректные значения пропускаются и протоколируются.
- Повторное обновление без изменений не выполняет лишнюю запись в БД.
- HTML-кэш очищается адресно для затронутых страниц каталога/разделов, включая `index@*.html`, а тегированный кэш — через Битрикс. При ошибке очистки сохраняется очередь `runtime/pending_cache.json`; **не удаляйте её без обработки**.
- Веб-страница `index.php` подключает шаблон Битрикс; CLI-синхронизация использует ядро для очистки кэша при наличии изменений или отложенной очереди.
- **Доступ к `runtime/` через HTTP должен быть закрыт на веб-сервере**, поскольку там находятся журналы, артикулы и служебная информация. Администраторская защита `index.php` сама по себе не защищает `runtime/`; запрет прямого доступа к этой папке необходимо отдельно проверить на новом хостинге.
- В BREXIT известны повторяющиеся артикулы (`2111027`, `4000504`, `4000506`, `4000514`, `4000516`); загрузчик выводит предупреждение и использует последнюю строку.
